### Production Host: `https://gateway.telepie.com/`

- Send SMS via API
    
    
    | Description | Public route for sending SMS messages |
    | --- | --- |
    | Endpoints |  **/client/v1/sms/message/send** |
    | Authorization | Bearer YOUR_API_KEY |
    | Content-Type | application/json |
    
    # Request Body
    
    | Field | Type | Required | Description |
    | --- | --- | --- | --- |
    | `templateId` | `string` | Yes | The approved SMS template ID. |
    | `type` | `"single"` | `"bulk"` | Yes | Determines whether a single or multiple recipients are being targeted. |
    | `contact` | `string` | Required when `type=single` | Recipient phone number in E.164 Must start with `+91` exactly 10 digit India after the country code
    
    Landline numbers are not supported |
    | `contacts` | `string[]` | Required when `type=bulk` | List of recipient phone numbers. Maximum 100 recipients per request. |
    | `vars` | `object` | No | Template variables grouped by recipient phone number. |
    | `headerId` | `string` | Yes | The approved SMS Header ID |
    
    # Template Variables
    
    Variables are mapped using the recipient's phone number as the key.
    
    Each object may contain any number of variables supported by the selected template.
    
    If no template variables are required, the `vars` field may be omitted.
    
    ```json
    {
      "+919876543210": {
        "var1": "John",
        "var2": "Order #1001"
      }
    }
    ```
    
    # Single Message Example
    
    ### When `type` is `"single"`
    
    - `contact` is required.
    - `contacts` must not be provided.
    - If `vars` is provided, it must contain an entry matching the value of `contact`.
    
    ```json
    {
      "templateId": "1707175021295946844",
      "headerId": "TEPLEP",
      "type": "single",
      "contact": "+919876543210",
      "vars": {
        "+919876543210": {
          "var1": "Faizan",
          "var2": "Telepie"
        }
      }
    }
    ```
    
    # Bulk Message Example
    
    ### When `type` is `"bulk"`
    
    - `contacts` is required.
    - Maximum of **100** recipients per request.
    - `contact` must not be provided.
    - If `vars` is provided:
        - Every recipient in `contacts` must have a matching entry.
        - No additional phone numbers are allowed inside `vars`.
    
    ```json
    {
      "templateId": "1707175021295946844",
       "headerId": "TEPLEP",
      "type": "bulk",
      "contacts": [
        "+919876543210",
        "+919999999999",
        "+918888888888"
      ],
      "vars": {
        "+919876543210": {
          "var1": "Faizan",
          "var2": "Order #1001"
        },
        "+919999999999": {
          "var1": "Rahul",
          "var2": "Order #1002"
        },
        "+918888888888": {
          "var1": "Amit",
          "var2": "Order #1003"
        }
      }
    }
    ```
    
    # Success Api Response
    
    > A successful `202 Accepted` response only indicates that the request has been accepted for processing. It does not guarantee message delivery.
    > 
    
    | Field | Type | Description |
    | --- | --- | --- |
    | `operationId` | `string` | Unique identifier for this API operation. |
    | `batch.id` | `string` | Batch identifier generated by the platform. |
    | `batch.type` | `string` | Either `single` or `bulk`. |
    | `summary.total` | `number` | Total messages received in the request. |
    | `summary.accepted` | `number` | Number of messages accepted for processing. |
    | `messages[].messageId` | `string` | Unique message identifier. |
    | `messages[].contact` | `string` | Recipient phone number. |
    | `messages[].status` | `string` | Initial processing status. |
    | `messages[].acceptedAt` | `ISO UTC string` | Initial processing status. |
    - **✅ Response 202 Accepted**
        
        ```json
        {
          "operationId": "tUFwObcrj5AEtUF",
          "batch": {
            "id": "0WoC9WEBBQpFe9f",
            "type": "single"
          },
          "summary": {
            "total": 1,
            "accepted": 1
          },
          "messages": [
            {
              "messageId": "RhQs38F669EtzLz",
              "contact": "+919696293133",
              "status": "accepted",
              "acceptedAt": "2026-08-12T05:38:00.000Z"
            }
          ]
        }
        ```
        
- Get all messages which sent via public API
    
    Returns a paginated list of SMS messages for your organization. You can filter results by message ID, phone number, template, header, delivery status, and submission date.
    
    ## Endpoint
    
    `POST /client/v1/sms/message/get`
    
    ---
    
    ## Authentication
    
    Requires a valid API key.
    
    ## Headers
    
    | Header | Required | Description |
    | --- | --- | --- |
    | `Authorization` | Yes | Bearer token used to authenticate the request. |
    
    ### Example
    
    ```
    Authorization: Bearer tp-xxxxxxxxxxxxxxxxxxxxxxxx
    ```
    
    ---
    
    ## Request Body
    
    | Field | Type | Required | Description |
    | --- | --- | --- | --- |
    | `messageId` | `string` | No | Filter messages by a specific message ID. |
    | `phone` | `string` | No | Filter messages by recipient phone number. |
    | `templateId` | `string` | No | Filter messages sent using a specific template. |
    | `headerId` | `string` | No | Filter messages sent using a specific SMS header. |
    | `status` | `string[]` | No | Filter messages by one or more statuses. Supported values are `pending`, `created`, `sent`, `delivered`, and `failed`. |
    | `dateRange` | `object` | No | Filter messages submitted within a date range. |
    | `dateRange.from` | `string` | Yes* | Start date in ISO 8601 format. Automatically normalized to `00:00:00.000 UTC`. |
    | `dateRange.to` | `string` | Yes* | End date in ISO 8601 format. Automatically normalized to `23:59:59.999 UTC`. |
    | `pagination` | `object` | Yes | Pagination configuration. |
    | `pagination.page` | `number` | No | Page number to retrieve. Default: `1`. |
    | `pagination.pageSize` | `number` | No | Number of records per page. Default: `20`. Maximum: `100`. |
    
    > **Note:** When `dateRange` is provided, both `from` and `to` fields are required.
    > 
    
    ---
    
    ## Example Request
    
    ```json
    {
      "templateId": "CzznkUFCod9VAe6",
      "headerId": "F62k6uvLRSy1HIY",
      "phone": "+919871423350",
      "status": [
        "created",
        "delivered"
      ],
      "dateRange": {
        "from": "2026-07-01T00:00:00.000Z",
        "to": "2026-07-31T23:59:59.999Z"
      },
      "pagination": {
        "page": 1,
        "pageSize": 20
      }
    }
    ```
    
    ---
    
    # Success Response
    
    **Status:** `200 OK`
    
    ## Response Body
    
    | Field | Type | Description |
    | --- | --- | --- |
    | `messages` | `array` | List of SMS messages matching the applied filters. Each item contains the message, batch, template, and header details. |
    | `count` | `number` | Total number of records matching the applied filters. |
    
    Each item inside the `messages` array contains the following objects.
    
    ---
    
    ## Message Object
    
    | Field | Type | Description |
    | --- | --- | --- |
    | `id` | `string` | Unique message identifier. |
    | `organizationId` | `string` | Organization identifier. |
    | `userId` | `string | null` | User that created the message. |
    | `batchId` | `string` | Batch identifier. |
    | `providerBatchId` | `string | null` | Provider-assigned batch identifier. |
    | `contact` | `string` | Recipient phone number. |
    | `vars` | `object | null` | Template variables used while sending the message. |
    | `status` | `string` | Current delivery status. |
    | `error` | `string | null` | Provider error message, if available. |
    | `errorCode` | `number | null` | Provider error code, if available. |
    | `submittedAt` | `string` | Message submission timestamp (UTC). |
    | `sentAt` | `string | null` | Message sent timestamp (UTC). |
    | `deliveredAt` | `string | null` | Message delivered timestamp (UTC). |
    | `failedAt` | `string | null` | Message failure timestamp (UTC). |
    | `createdAt` | `string` | Record creation timestamp. |
    | `updatedAt` | `string` | Record last update timestamp. |
    
    ---
    
    ## Batch Object
    
    | Field | Type | Description |
    | --- | --- | --- |
    | `id` | `string` | Batch identifier. |
    | `type` | `string` | Batch type. Possible values: `single`, `bulk`. |
    | `status` | `string` | Batch processing status. Possible values: `created`, `running`, `completed`. |
    | `totalMessages` | `number` | Total number of messages in the batch. |
    | `awaitedMessages` | `number` | Number of messages acknowledged by the provider. |
    | `createdAt` | `string` | Batch creation timestamp (UTC). |
    
    > **Note:** The batch object no longer includes `organizationId`, `userId`, `templateId`, `headerId`, or `updatedAt`.
    > 
    
    ---
    
    ## Template Object
    
    | Field | Type | Description |
    | --- | --- | --- |
    | `id` | `string` | Internal template identifier. |
    | `templateId` | `string` | DLT template ID. |
    | `templateName` | `string` | Template name. |
    | `templateUseCase` | `string` | Template use case, such as `transactional`, `promotional` or `otp`. |
    | `textMessage` | `string` | SMS message content. |
    | `status` | `string` | Template approval status. |
    
    ---
    
    ## Header Object
    
    | Field | Type | Description |
    | --- | --- | --- |
    | `id` | `string` | Internal header identifier. |
    | `header` | `string` | SMS sender ID (Header). |
    | `dltId` | `string` | DLT header ID. |
    | `entityId` | `string` | DLT entity ID associated with the header. |
    | `entityName` | `string` | Registered DLT entity name. |
    | `status` | `string` | Header approval status. |
    
    ---

    ## Notes
    
    - All timestamps are returned in **UTC**.
    - Every item in the `messages` array contains four objects:

    - The `template` object contains the complete template metadata associated with the message.

    - Multiple statuses can be supplied in the `status` filter.
    - The `vars` field contains the template variables used while sending the message and may be `null`.
    - Date filtering is inclusive. The API automatically normalizes the start date to the beginning of the day and the end date to the end of the day.
    - The maximum supported `pageSize` is **100**.
    - If no filters are provided, the endpoint returns paginated messages for your organization.
- Get Templates
    
    Returns SMS templates available for your organization. You can retrieve a specific template by its ID or filter templates by their approval status.
    
    ## Endpoint
    
    `POST /client/v1/sms/template/get`
    
    ---
    
    ## Authentication
    
    Requires a valid API key.
    
    ## Headers
    
    | Header | Required | Description |
    | --- | --- | --- |
    | `Authorization` | Yes | Bearer token used to authenticate the request. |
    
    ### Example
    
    ```
    Authorization: Bearer tp-xxxxxxxxxxxxxxxxxxxxxxxx
    ```
    
    ---
    
    ## Request Body
    
    | Field | Type | Required | Description |
    | --- | --- | --- | --- |
    | `templateId` | `string` | No | Internal template identifier. |
    | `status` | `string[]` | No | Filter templates by one or more statuses. Supported values: `approved`, `pending`, `rejected`. |
    
    ---
    
    ## Example Request
    
    Retrieve a specific template.
    
    ```json
    {
      "templateId": "CzznkUFCod9VAe6"
    }
    ```
    
    Filter templates by status.
    
    ```json
    {
      "status": [
        "approved",
        "pending"
      ]
    }
    ```
    
    Retrieve all templates.
    
    ```json
    {}
    ```
    
    ---
    
    # Success Response
    
    **Status:** `200 OK`
    
    Returns an array of template objects.
    
    ## Template Object
    
    | Field | Type | Description |
    | --- | --- | --- |
    | `id` | `string` | Internal template identifier. |
    | `templateName` | `string` | Template name. |
    | `templateId` | `string` | DLT template ID. |
    | `templateUseCase` | `string` | Template use case (for example, `transactional`). |
    | `status` | `string` | Template approval status. Possible values: `approved`, `pending`, `rejected`. |
    | `textMessage` | `string` | SMS template content. |
    | `createdAt` | `string` | Template creation timestamp (UTC). |
    | `header` | `object` | Associated SMS header. |
    | `header.header` | `string` | Registered SMS header. |
    | `user` | `object | null` | User who created the template. |
    | `user.name` | `string` | User's name. |
    | `user.email` | `string` | User's email address. |
    
    ---
    
    ## Example Response
    
    ```json
    [
      {
        "id": "CzznkUFCod9VAe6",
        "templateName": "Welcome Message",
        "templateId": "1707175021295946844",
        "templateUseCase": "transactional",
        "status": "approved",
        "textMessage": "Thank you for choosing Telepie Technology for your SMS vendor.",
        "createdAt": "2026-07-08T06:10:50.147Z",
        "header": {
          "header": "TELPIE"
        },
        "user": {
          "name": "Mohammad Naushad",
          "email": "fowad@telepie.com"
        }
      }
    ]
    ```
    
    ---
    
    ## Notes
    
    - If `templateId` is provided, only the matching template is returned.
    - Multiple statuses can be supplied in the `status` filter.
    - If no filters are provided, all templates available to your organization are returned.
    - All timestamps are returned in UTC.

# Our Standard Error Response

> A error `4xx failed` all errors follow the same response format.
> 

```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Human readable message",
    "details": {}
  }
}
```

| Field | Type | Description |
| --- | --- | --- |
| `error.code` | `string` | Machine-readable error code. |
| `error.message` | `string` | Human-readable error description. |
| `error.details` | `object` | Additional information, when available. |
- ❌ 400 Bad Request
    
    ```json
    {
      "error": {
        "code": "VALIDATION_ERROR",
        "message": "Validation failed.",
        "details": {
          "...": "..."
        }
      }
    }
    ```
    
- ❌ 401 Unauthorized
    
    ```json
    {
      "error": {
        "code": "UNAUTHORIZED",
        "message": "Authorization header is missing."
      }
    }
    ```
    
    Invalid Authorization header.
    
    ```json
    {
      "error": {
        "code": "INVALID_AUTHORIZATION_HEADER",
        "message": "Authorization header must use the Bearer authentication scheme."
      }
    }
    ```
    
    Invalid API key.
    
    ```json
    {
      "error": {
        "code": "INVALID_API_KEY",
        "message": "The provided API key is invalid."
      }
    }
    ```
    
- ❌ 403 Forbidden
    
    The API key has exceeded the configured SMS frequency limits.
    
    ```json
    {
      "error": {
        "code": "FORBIDDEN",
        "message": "SMS sending limit exceeded."
      }
    }
    ```
    
- ❌ 404 Not Found
    
    Referenced resources (such as a template) could not be found.
    
    ```json
    {
      "error": {
        "code": "NOT_FOUND",
        "message": "The requested resource was not found."
      }
    }
    ```
    
- ❌ 409 Conflict
    
    The request conflicts with the current state of the resource.
    
    ```json
    {
      "error": {
        "code": "CONFLICT",
        "message": "The request could not be completed due to a conflict."
      }
    }
    ```
    
- ❌ 429 Too Many Requests
    
    The client has exceeded the API rate limit.
    
    ```json
    {
      "error": {
        "code": "TOO_MANY_REQUESTS",
        "message": "Too many requests."
      }
    }
    ```
    
- ❌ 500 Internal Server Error
    
    An unexpected server error occurred.
    
    ```json
    {
      "error": {
        "code": "INTERNAL_SERVER_ERROR",
        "message": "An unexpected error occurred."
      }
    }
    ```
